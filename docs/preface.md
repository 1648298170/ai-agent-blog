# 前言：开始之前，先读这一篇

> 这是《AI Agent 全栈工程师 · 23 周通关教程》的开篇。用十分钟回答五个问题：这套课为什么存在、你是不是它的读者、23 周后你手里会有什么、该怎么学、以及它不会给你什么。读完再决定是否翻开 [Day 1](/week01/day1)。

## 一、这套课为什么存在

它要填的缺口一句话说得清：**你知道每天该做什么，但没人教你怎么学会**。

配套的《23 周每日执行手册》是一份精确到天的执行清单——第 12 周 Day 4 写着"用 LangGraph 实现裸 ReAct 循环"。清单很清楚，但一个没接触过 LangGraph 的人看着这行字，接下来的一小时大概率在三个地方打转：官方文档（准确但零散，像字典不像教材）、视频课程（录制时的新技术，上线时已经过时）、博客文章（质量参差，各讲一角拼不成全景）。

这套教程就是那个缺口本身的答案：**161 篇日课 + 2 篇加餐，每天一篇，把手册里的一句话任务展开成"概念讲解 → 可运行代码 → 常见踩坑 → 自测题"的完整教学**。三个设计决定让它区别于上面三类资源：

1. **连贯叙事**：不是 161 篇独立文章，是一个故事——你从第 1 周搭的 pnpm monorepo，到第 23 周还在用；第 5 周存进 PG 的 token 黑名单，第 6 周亲手迁去 Redis
2. **同一个项目贯穿**：23 周你只建一个平台，每周给它加一块能力，五个里程碑是它成长的五张照片
3. **按写作当下的技术现状写**：版本红线（LangChain 1.0 的 API 变更、MCP 无状态规范、ESLint 9 平铺配置……）全部显式标注，不让你拿着 2023 年的写法调 2026 年的工具

## 二、开始之前，确认你是谁

这套课为这样的读者而写：**会 JavaScript，想用 23 周转型企业级 AI Agent 全栈工程师的人**。

三项硬性前置，缺一先补：

| 前置 | 到什么程度算够 | 不够去哪补 |
| ---- | ---- | ---- |
| JavaScript | 函数/类/模块/async-await 能读懂并手写 | 现代 JS 任意入门教程 |
| 开发环境 | 会用命令行、能装软件（Node、Docker、Python） | 各官网安装文档 |
| 一台电脑 | 16G 内存起步（要同时跑 Docker 全家桶 + 编辑器） | — |

一项软性前置，比技术更硬：**时间**。每天 2–3 小时 × 23 周 ≈ **500 小时**。这是诚实数字，不是营销数字——报着"周末突击一下"的预期进来，会在第 6 周（并发控制）或第 16 周（评估工程）撞墙。可以慢，不建议断。

## 三、23 周后，你手里会有什么

这条路上有几条看不见的线，走的时候会越来越清楚：第 4 周建的 PostgreSQL，第 14 周要装 pgvector 变成向量库；第 5 周签发的 JWT，第 20 周要贯通全平台；第 1 周搭的 monorepo，装着这 23 周的所有代码——**你始终在同一个项目上工作，它跟着你长大**。

**五个里程碑项目**，每个都可运行、可演示、可写进简历：

| 里程碑 | 周次 | 是什么 |
| ---- | ---- | ---- |
| v1 | 第 4 周 | monorepo 全栈 CRUD：Next.js + NestJS + PostgreSQL + Prisma 联调跑通 |
| v2 | 第 8 周 | 上线：Docker + CI/CD + 云部署 + HTTPS + 监控告警 |
| v3 | 第 13 周 | 多 Agent 平台：LangGraph + ReAct + 人工审批 + 流式 UI |
| v4 | 第 19 周 | 生产级加固：RAG 引用溯源 + 评估门禁 + 记忆 + MCP + 纵深防御 |
| 终点 | 第 22–23 周 | STAR 文档 + 简历 + 模拟面试记录 + 面试速查卡 |

**一张技术全景**：TypeScript → Next.js/NestJS → Redis/消息队列 → Docker/K8s 前夜 → Python/FastAPI → LLM 原生 API → LangGraph → RAG → Agent 评估 → 记忆与上下文工程 → MCP/A2A → 安全 → 生产化（可观测/成本/限流）。

但比清单更值钱的是**可解释的架构决策**。每个里程碑的 Day 7 都要求你用 STAR 法则复盘"为什么这么设计、权衡过什么替代方案"——面试官问"为什么用 LangGraph 不用裸 while 循环"时，背答案的人和做过决策的人，三句话就分出来了。

这一切最终对准三个可直接落地的产品方向：**知识库问答**（第 14–15 周）、**文档智能**（第 14 周）、**客服系统**（第 12–13 周 + 第 20 周平台化）——引擎是同一套，产品是三种车身。每条产品线都配了标杆产品与开源实现供你对照校准，见[学习指南](/guide/)。

## 四、怎么学：四条铁律

1. **代码自己敲**。教程的代码块都可直接复制，但复制粘贴的手感不会变成你的手感。敲错、报错、修错，是学习本身，不是学习的障碍
2. **不跳周**。依赖链是实打实的：第 4 周建的数据库，第 14 周要装 pgvector 扩展；第 5 周写的认证，第 20 周要贯通成统一身份链。跳过去省的一周，会在后面加倍还
3. **Day 7 的复盘不许跳**。每周最后一天画架构图、写周记、做自检清单——它对抗的是遗忘曲线，跳过它等于前面的六天打了七折
4. **自测答不上来就回读**。每天文末 4–6 道自测题是唯一的进度裁判，答不上来说明"看过"还没变成"会了"

卡住了怎么办：先查当天的"常见踩坑"（八成在里面）→ 再搜报错信息 → 还不行就带着完整报错上下文问 AI 或社区。更多日常节奏见[使用指南](/guide/)。

## 五、关于版本：这门课的"保质期"声明

教程内容按 **2026 年 9 月**的技术现状写成。你读到它的时间越晚，越可能遇到"教程写的 API 和官方文档对不上"——这不是 bug，是 AI 工程领域的日常。遇到时按这个顺序处理：

1. 先查官方文档/changelog 确认 API 是否已变（教程里到处是版本红线标注，就是给你这个判断做参照的）
2. API 变了：思路通常不过时，按新签名改写——这本身就是课程想教你的能力，**版本敏感度是 AI 工程师的核心工程素养**
3. 拿不准：框架会变，但"为什么需要它、它解决什么问题"的部分几乎不变，先回到概念讲解重新理解

## 六、这门课不做什么

诚实边界，提前对齐预期：

- **不教 JavaScript 零基础**。var 和 let 的区别、Promise 链怎么读，默认你已掌握
- **不是算法全科**。只在第 23 周补 Agent 岗位高频的图与优先队列，冲大厂算法岗请另行系统刷题
- **不承诺结果**。它承诺的是一条被验证过的路径和 500 小时的密度，offer 是路径的副产品
- **主线是深度开发，不是低代码**。Dify/Coze 在第 19 周有上手教学（国内 JD 的高频筛选词），但定位是加分项——你的核心身份是"能自建 LangGraph 的那个人"
