## 二、演进方向：从 BACKLOG 里挑真实条目

[BACKLOG.md](https://github.com/1648298170/ai-agent-blog/blob/main/agent-app/BACKLOG.md) 的纪律是「挂账不遗忘，到触发条件再开工」——以下按主题归组，每项都有真实设计稿：

**① 多 Agent 协作（三阶段已挂账）**。教学主张先立住：多 Agent = 单 Agent 的乘法，不是玄学——每个「Agent」就是独立 system prompt + 独立职责 + 受控输入输出的 `runToolLoop` 组合；新问题只有三个：**分工**（谁干）、**共享状态**（互相知道什么）、**质量闭环**（谁验收）。三阶段：

```text
P1 升格叙事（零代码）  service/README 增补「你就是多 Agent：Supervisor 模式」
                      ——路由 Agent + 三个专家工人 + HandoffPack 交接，
                      你在 09 站已经写过它，只是没这么叫
P2 teams/ 流水线       planner（规划）→ executor（逐步执行）→ critic（验收打回）
                      共享黑板做单一事实源；全程 trace，🧩🔧🔍 区分角色
P3 A2A 落地            Agent Card 对外发布（GET /.well-known/agent-card.json），
                      起两个实例互相委托「查订单」，把协议跑成狗粮
```

P2 的示例目标设计得很妙：「查订单 A-1024，未发货就建催发工单」——正好逼出规划/执行/验收三分工。风险也在账上写死了：planner 的计划 JSON 不稳（宽松解析 + 重试一次 + 失败降级单步）、critic 打回死循环（重试上限 2 次，超限带「未完全达成」诚实收尾）——你看，又是熟悉的「防御先行」味道。

**② 压缩水位线升级**。条数阈值（40 条）不是 token 的合格代理——40 条「你好」和 40 条 10KB 日志天差地别。工业做法：水位线 = 模型上下文窗口 × (1 − 25% buffer)，估算三层（上次 usage 回馈校准 / 字符×模型系数 / 无数据退回条数兜底），压到窗口 50% 水位。改动边界只有一个文件（`compression.ts`），接口接缝就是为此留的。

**③ 重试与退避**。LLM 调用无 429/5xx 指数退避 + 抖动——模型调用失败即失败。先核实 ai SDK 内置重试的边界，再补应用层策略。

**④ 生产壳**：认证 / RBAC 多租户 / 限流 / CORS 收紧。web/api 目前对公网裸奔（11 站诚实清单原文）。

**⑤ 在线评估**。76 例是离线考卷；真实流量回流成数据集（trace 里躺着现成的样本），「有真实流量后」是它的触发条件——你自己的项目有流量那天，就是开工那天。

**⑥ 语义缓存与成本面板**。pgvector 存「问题 → 答案」，相似问题直接命中不再调模型；配套 token 用量聚合（usage 现在飘过就丢）。素材：[week21 Day 6](/archive/weeks/week21/day6)。

**⑦ OTel 可观测**。结构化日志 + 请求关联 ID 贯穿 + OTel GenAI 规范的 trace 导出——从 stderr 图标流升到工业级三件套（日志/指标/追踪）。素材：[week21 Day 1](/archive/weeks/week21/day1)。

**先做哪个**？按「设计稿完整度 ÷ 改动边界」排序：压缩水位线最适合先动手（设计稿带验收标准，只动 `compression.ts` 一个文件）；重试退避次之（工业差距审查的 bug 级条目）；生产壳与 OTel 等你有真实部署再开——BACKLOG 的触发条件纪律本来就是「到条件再开工，不提前透支」。

## 三、生态选型观：框架与平台的边界

学完手写再看生态，你的视角和入门者完全不同（素材：[week12 加餐 · LangChain 生态地图](/archive/weeks/week12/langchain)）：

- **LangChain/LangGraph 不是一个框架，是一组分层的库**：core（消息/工具/模型抽象）、langchain 1.0（`create_agent` + middleware 快捷方式）、langgraph（编排引擎）、langsmith（可观测）。`create_agent` 幕后生成的正是你在 02 站手写的那约 30 行装配与路由——学手写不是为了拒绝快捷方式，是为了快捷方式对你不再是黑盒。
- **旧范式为什么死，看一眼就懂**：LCEL 的管道符 `|` 串的是直线（`prompt | llm | parser`），装不下 Agent 的环——执行工具、回填、再调模型的循环它从语法上就表达不了，这是旧 Chains 整体归进 classic 遗留包的根本原因。1.0 的扩展点是 middleware：`SummarizationMiddleware`（历史超阈值自动摘要——你在 03 站手写过的东西）、`HumanInTheLoopMiddleware`（工具执行前等人批准——你在 05 站套过的壳）。框架的进化方向，正是把你手写的那些「壳」收编成配置项。
- **Dify / Coze 是低代码平台**（素材：[week19 Day 5](/archive/weeks/week19/day5) · [Day 6](/archive/weeks/week19/day6)）：把高频管道固化成拖拽节点，原型半天出师；代价是表达力锁死在节点类型提供的范围里。平台「到顶」的三个信号：多 Agent 状态机、深度人机协同、评估体系——见一个就知道该回代码了。选型先答三个问题，答案自己会浮出来：

| 问题 | 云端 Coze | 自托管 Dify | 自建（手写/框架） |
|---|---|---|---|
| 数据能不能出域？ | 不出域就排除它 | ✓ 数据在自己服务器 | ✓ |
| 逻辑有多复杂？ | 高频管道内很快 | 到顶三信号出现就回代码 | 任意复杂度 |
| 谁长期维护？ | 无需运维 | 要管一套 compose | 要管代码本身 |

立场一句话：**框架是省事，代价是黑盒；手写版的可控性在你需要深度定制时完胜**。什么时候该用框架？——02 站岔路 3 给过答案：当你发现自己在循环里重复造「消息裁剪 / 工具缓存 / 并行调度」这三个轮子时。在那之前，手写。

## 四、面试衔接：把这段经历变成 offer

主线十二站是一份现成的项目叙事，归档里备好了冲刺材料：

- **[week22 · 系统设计与复盘](/archive/weeks/week22/)**：系统设计方法论（缓存三件套 / 队列 / 异步任务）、STAR 法则复盘三个里程碑、简历写成成果导向——你的「里程碑」就是 agent-app 这套东西；
- **[week23 · 面试冲刺](/archive/weeks/week23/)**：Agent 八股（ReAct / RAG / MCP / A2A / 评估 / 安全 / 框架对比——每一样你都做过实物）、模拟面试、面试速查卡。

被问「你会 LangChain 吗」，低分答法是背组件名；高分答法是从分层开始答，最后补一句「等价的循环我自己手写过」——这半句你现在说得出口。

STAR 复盘也不用编——随手起一个头：**S**（客服 Agent 有建单这类高危写操作）→ **T**（模型好心办坏事怎么办）→ **A**（审批壳挂起等人裁决 + 幂等壳防重复执行，叠加顺序是审批在外幂等在内）→ **R**（同会话重复建单实测拿到同一个工单号；60s 超时自动拒绝）。一段话四个坑全是你踩过的实录。

两份材料共同的动作是「把做过的事翻译成面试官听得懂的语言」——翻译的原材料，第一节那张表已经给全了。

## 五、收尾：闭环已走通，起点永远在

回看这条线：从一次裸的 `generateText` 出发，加了手（工具循环）、加了记性（三层记忆）、加了书架（RAG）、戴了护具（护栏）、进了考场（评估）、组了产品（路由客服）、画了脸（SSE 前端）、落了地（容器部署）——**从 0 到生产的完整闭环，每一环都是你自己敲出来的**。

Agent 这个领域还在高速变化，但你在 02 站握住的那台发动机不会过时：所有新框架剥到最里层都是它。往后无论工具怎么换，你都有能力拆开看。

三个习惯值得带走，它们比任何一节知识都耐用：**跑起来再说**（每站的第一节永远是「先有体感」）、**诚实标注边界**（不知道就说不知道，没做就写进清单——本教程的成熟度矩阵就是这个习惯的产物）、**用证据检验**（改 prompt 前后跑分、切存储后进数据库数行数——「我认为」不算数，「我验证过」才算）。

下一步的起点也早写好了：**往 `examples/` 里加一个自己的工具**（[扩展指南](/how-to/EXTENDING) 三件套：description / zod schema / execute）——从那里长出来的，可能就是你的下一个项目。

去吧。

## 自测题（先凭记忆答，再展开）

1. 多 Agent 相对单 Agent 只多出哪三个新问题？`teams/` 流水线里 planner / executor / critic 分别对应哪个？
2. 「什么时候该用框架」的判断标准是什么？为什么说学过手写的人用框架更有优势？
3. 压缩水位线升级要替代什么现状？估算三层指哪三层？

<details><summary>答案</summary>

1. 分工（谁干什么）、共享状态（互相知道什么）、质量闭环（谁验收）；planner 对应分工、blackboard 对应共享状态、critic 对应质量闭环（executor 是干活的工人）。
2. 当你发现自己在重复造「消息裁剪 / 工具缓存 / 并行调度」三个轮子时（02 站岔路 3）；手写过的人知道框架幕后的每一根线怎么接——快捷方式行为不对时能拆开看，不是黑盒。
3. 替代「写死 40 条消息触发压缩」的条数阈值（条数不是 token 的合格代理变量）；三层 = 上次 generateText 的 usage 回馈校准、字符数×模型系数估算、无任何数据时退回条数兜底（向下兼容）。
