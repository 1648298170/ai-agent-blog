# 第 22 周 · Day 7：简历定稿方法论——让反馈决定最后一稿

> 手册任务：周复盘 + 整理。根据模拟面试反馈修正简历和项目描述，写 300 字周记，当日产出：简历终稿 + 周记。
> 本篇解决的问题只有一个：简历怎么从"自己觉得行"变成"经得起面试官追问"。

## 今日目标

1. 重放 Day 6 的模拟面试记录，把卡壳和含糊的地方列成反馈清单，逐条改进简历
2. 过一遍 10 项定稿 checklist，导出终稿 PDF，按四段模板写一篇 300 字周记
3. 做完 10 题自检清单，答不上来的标记出来，回读对应 Day 的教程

## 概念讲解：为什么定稿靠反馈，不靠再润色一遍

先说一个不舒服的事实。你改了五遍的简历，在你眼里信息量饱满，因为你脑子里装着全部上下文：你写"优化了流式链路"，自己知道那是三天的调参、两次重构、一版压测报告。但简历的读者没有这些上下文。HR 扫一眼只看到五个字，面试官只看到一道追问的靶子。

这和第 1 周 Day 7 说的是同一件事的两面：**你读自己的简历，是在做识别；别人读你的简历，是在做提取**。识别永远比提取舒服，所以"我自己再读一遍感觉挺顺"这句话没有任何证明力。证明确实有效的只有一个东西：外部反馈。

好在昨天的模拟面试就是现成的压力测试。两类反馈直接可用：卡壳的问题，对应简历上"写了但撑不住"的表述；AI 面试官点出的模糊处，对应"写了但没写清"的地方。今天的定稿不是重新排版，是**拿着反馈清单逐条动刀**：

| 反馈来源 | 逼出什么 | 对应今天的产出 |
| --- | --- | --- |
| 模拟面试记录 | 哪些表述经不起追问 | 修正后的项目描述 |
| 10 项定稿 checklist | 格式与完整性漏洞 | 简历终稿 PDF |
| 300 字周记 | 本周认知变化 | 四段周记 |
| 10 题自检 | 知识是否真的进了脑子 | 标记回读清单 |

还要记住简历的第一道关不是人，是流程。一份简历通常要过三关：ATS 机器按关键词打分、HR 花 10 到 15 秒扫一眼、面试官拿着追问清单读项目段。每一稿都要同时过三关，checklist 就是照这三关设计的。

::: tip 复盘流程和第 1 周一样，标准不一样了
四段周记、自检清单、git 收口，这套流程从第 1 周 Day 7 用到今天没变过。变的是今天的产出第一次面向外部：简历终稿是要发给真公司的文件，验收标准从"自己满意"换成了"对方挑不出毛病"。
:::

## 核心知识

### 1. 简历定稿 checklist（10 项）

逐项打勾，全过才算终稿。任何一项过不了，回到对应位置改，别跳。

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 一页纸 | 中文单页，删到每一行都在争位置。放不下的经历就不配占位置 |
| 2 | JD 关键词覆盖 | 目标 JD 里的技术词（Kafka、Redis、LangGraph、SSE）在你的简历里逐个出现，词面要完全一致 |
| 3 | 每条有量化 | 每条项目经历至少一个数字：延迟、QPS、提升百分比、数据规模 |
| 4 | STAR 完整 | 每条描述能补全 S/T/A/R，A 段写的是你的决策和动作，不是团队流水账 |
| 5 | 无错别字 | 出声读一遍，再让 AI 或朋友帮看一遍。错别字在 HR 眼里等于不认真 |
| 6 | 文件名规范 | `姓名-岗位-简历.pdf`，例如 `张三-后端开发-简历.pdf`。禁止"最终版v3真最终" |
| 7 | PDF 格式 | 用 PDF 不用 docx，任何设备打开排版不跑。导出后自己先在手机上开一遍 |
| 8 | 项目链接 | GitHub 仓库 + 博客线上地址都放上。你写了 22 周的博客此刻就是作品集，线上地址必须能点开 |
| 9 | 技能分档诚实 | 精通/熟悉/了解三档，每一档都经得起对应深度的追问，拿不准就降一档 |
| 10 | 联系方式 | 手机和邮箱准确无误，GitHub 和博客链接用手机实际点开验证过 |

第 8 项多说一句。别人的作品集要另外准备，你的作品集这 22 周一直在写：每周的教程、架构图、周记、复盘，全在线上。面试官点开博客看到的是 22 周持续学习的证据，这比简历上任何一句自评都有说服力。所以链接必须放，而且必须验证可访问。

### 2. 300 字周记模板

模板没变，还是四段，记认知变化不记流水账：

1. **本周最大的收获**：用自己的话说，禁止抄教程原句
2. **卡得最久的一个问题**：以及怎么解决的，下周大概率还会撞上同类问题
3. **还含糊的概念**：诚实列出来，它是下周的输入
4. **下周开始前要补什么**：留具体动作，能执行的那种

第 22 周示例，照这个密度写：

```text
① 本周最大收获：系统设计面试考的是过程不是背答案，45 分钟五阶段是把
模糊需求推成可落地方案的脚手架。而我最大的底牌是 21 周亲手建的平台，
每个组件背后都有真实数字兜底。
② 卡得最久：STAR 的 A 段。第一稿全写成"我们做了什么"，被 AI 面试官
一句"那你在哪里"问住，重写时每条都过一遍"换个人能不能照抄"，能照抄
的就重写。
③ 还含糊：缓存雪崩的多级缓存方案只记住了名词，没在自己的平台落过地；
队列的死信处理流程说不完整。
④ 下周前补：给 Day 3 的队列方案补一段死信队列的设计，写完能脱稿讲。
```

### 3. 第 22 周知识自检清单

规则和往常一样：每题先自己口头回答，说完整了再点开答案对照。说不出来的记下题号，回读对应 Day 的教程。

**问题 1：45 分钟标准流程的五个阶段是什么？各占几分钟？（Day 1）**

::: details 答案
需求澄清 0 到 5 分钟，高层设计 5 到 15 分钟，深入组件 15 到 30 分钟，瓶颈与演进 30 到 40 分钟，总结 40 到 45 分钟。时间盒不是死规定，本质是让面试官在任意时刻打断你，看到的都是结构化思考。
:::

**问题 2：缓存三件套的 30 秒版，每个问题一句话加一句防护。（Day 2）**

::: details 答案
穿透：查根本不存在的数据，缓存永远不命中，请求全打数据库，防护是缓存空值或前置布隆过滤器。击穿：某个热点 key 过期的瞬间大量并发直奔数据库，防护是互斥锁只放一个请求回源，或热点 key 不设过期。雪崩：大批 key 同时过期或缓存整体宕机，防护是过期时间加随机抖动、多级缓存、缓存集群高可用。
:::

**问题 3：队列三连问是哪三问？各自的答案核心？（Day 3）**

::: details 答案
为什么用队列：削峰、解耦、异步化长任务。消息会不会丢：三个环节逐个设防，生产者开确认、broker 落盘持久化、消费者处理完再手动 ack。重复消费怎么办：靠消费端幂等，业务唯一 ID 去重或状态机兜底，而不是指望消息系统恰好只投一次。
:::

**问题 4：STAR 里的 A 应该写什么？最常犯的错是什么？（Day 4）**

::: details 答案
写"你"做的动作和决策：选了哪个方案、为什么选它、放弃了什么、踩坑之后怎么改的。最常犯的错是写成团队流水账，通篇"我们"，或者 S 和 T 撑满两行、A 一笔带过。面试官的追问全打在 A 上，A 空了整条经历就空了。
:::

**问题 5：项目没上线、没有生产数据，量化数字从哪来？（Day 5）**

::: details 答案
三个来源：自己压测，用工具压出 QPS 和 P99；对照值，优化前后同一环境各测一次，写相对提升；规模估算，数据量、评测集大小、代码规模都算数。原则是数字可复现、测试条件说得清，不编生产环境的数字，被追问"怎么测的"要答得出来。
:::

**问题 6：简历项目描述的一句话公式是什么？（Day 5）**

::: details 答案
动词开头 + 具体技术动作 + 量化结果。例如：用 SSE 分片透传重构流式链路，把首 token 时间从 2.1 秒压到 0.9 秒。反例：负责平台后端开发。"负责""参与""了解"开头又没有数字的句子，等于没写。
:::

**问题 7：为什么简历必须贴着 JD 的关键词写？（Day 5）**

::: details 答案
因为初筛是关键词匹配。ATS 系统按 JD 里的词给简历打分，HR 人肉筛一份也就 10 到 15 秒，扫的是 JD 上的词有没有出现。你写"消息队列"，JD 写"Kafka"，机器不认同义词，匹配就是零。所以每投一个岗位，关键词那一栏要对着 JD 调一遍。
:::

**问题 8：用 AI 当模拟面试官，prompt 的核心要素有哪些？（Day 6）**

::: details 答案
四样：角色，设定为某方向的资深面试官，风格是逐层追问；输入，贴上目标 JD 和你的项目描述原文；规则，一次只问一个问题，答完追问一层为什么，至少追三层；输出，面完分维度打分，并引用你的原话指出哪里露馅。没有第四样的反馈，练十遍也不知道自己哪里弱。
:::

**问题 9：30 秒法则是什么？用在哪些地方？（Day 6）**

::: details 答案
任何被问到的问题，先用 30 秒给出结论或框架，再展开细节。对面试官，先听结论再决定往哪深挖；对你自己，先说框架等于给大脑争取整理细节的时间。项目介绍、系统设计总结段、被问住的瞬间，全都用得上。
:::

**问题 10：面试里当场卡壳，正确的处理方式是什么？（Day 6）**

::: details 答案
四步：先复述问题确认理解，顺便争取几秒；把确定的部分先说出来；给出推导路径，说出假设，从已知往未知推；确实不会就承认边界，再补一句换个环境你会怎么查证。最差的选择是硬编和长时间沉默，编错的代价远大于说"这块我没深入过"。
:::

::: tip 10 题全对也别飘
全对说明本周及格，不说明可以跳过复盘。简历 checklist、周记、git 收口三件事做完，本周才算收口。
:::

## 动手任务：定稿简历，收口本周

按顺序做完五步，预计 75 到 100 分钟。

**第一步：重放模拟面试记录（15 分钟）**

把 Day 6 的模拟面试记录翻出来，分两列列清单：左列写卡壳的问题和 AI 点名模糊的表述，右列写简历里对应的那句话。对不上的反馈单独放，那是要补的新内容。

**第二步：修正项目描述（25 分钟）**

每条卡壳反馈动一次刀。改法照两句口诀：撑不住的删掉或降档，没写清的按一句话公式重写。每改一条，心里追问一遍"为什么用这个方案"，答得出才算过关。

**第三步：过 checklist 导出终稿（20 分钟）**

10 项逐个打勾。全过之后导出 PDF，命名 `姓名-岗位-简历.pdf`，发到自己手机上打开，链接逐个点一遍。文件名里的姓名岗位换成你自己的。

**第四步：写 300 字周记（15 分钟）**

按四段模板写，对照示例的密度。"还含糊"那段别敷衍，它就是下周的补课清单。

**第五步：自检加 git 收口（20 分钟）**

10 题逐个口头回答，答不上的记下题号回读对应 Day。然后整理本周产物：

```bash
# 本周文档按类型分开提交：
git add docs/week22
git commit -m "docs(week22): 系统设计 + 简历定稿教程与周记"
git add resume
git commit -m "docs(resume): 简历终稿 v1.0"

# 打标签收口：
git tag week22-done
```

## 常见踩坑

**定稿变成再排版。** 字体调了、间距调了、图标换了，内容一个字没动。这不是定稿，这是美工。定稿的唯一依据是反馈：模拟面试里哪里卡壳，简历里就改哪里。

**量化数字现场编。** 为了好看写个"支撑 10 万 QPS"，面试官问怎么测的当场翻车。没上过线就写压测数据和相对提升，标清测试条件，可复现比好看重要。

**博客链接忘了放，或者放了没验证。** 22 周的线上笔记是你最硬的证据，不放等于白攒。放完必须自己点开验证，一个 404 比不放更减分。

**周记的"还含糊"写"无"。** 写"无"多半是在回避，不是真的没有。真没有含糊概念的求职周，不存在。
