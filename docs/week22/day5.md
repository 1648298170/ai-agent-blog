# 第 22 周 · Day 5：简历优化——把项目写成「成果导向」

> 对应手册任务：学习「简历优化：把项目写成成果导向」，动手「用量化结果 + 技术关键词重写项目描述」，产出「简历初稿」。本篇只解决一个问题：昨天 STAR 文档里几百字的项目故事，怎么压成简历上三五行，让 HR 十秒内扫到关键词、面试官一眼看到成果。

## 今日目标

1. 说得清简历筛选的两道关卡，十秒人眼和关键词过滤，以及流水账分别死在哪一关
2. 掌握一句话公式：动作动词 + 做了什么 + 技术栈 + 量化结果，能把任何一条 STAR 改写成简历语言
3. 独立完成三个里程碑的重写和技能栏三档划分，拼出一份正好一页的简历初稿

## 概念讲解：为什么你的简历活不过 10 秒

先接受一个事实：一份简历在 HR 手里的平均停留时间约十秒。热门岗位收上百份简历，没人逐字读。过了人眼这关，很多公司还有系统做关键词初筛，JD 里的高频词在你简历里一次都不出现，直接沉底。

所以简历有三个读者：疲倦的 HR 扫结构，冷冰冰的系统扫关键词，终于点开简历的技术面试官扫成果。流水账对三个读者全部失效。看一段典型流水账：

```
负责客服 Agent 系统的整体开发工作，使用 LangGraph 框架，
实现了多个 Agent 模块，解决了开发中遇到的问题，优化了系统性能。
```

这段话的问题不是写错，而是没有信息量。「负责」「实现了多个模块」放哪个项目上都成立，等于什么都没说；「优化了性能」没有数字，没法验证也没法比较。而 AI Agent 岗 JD 里的高频词，LangGraph、RAG、MCP、Agent 评估、多 Agent、Function Calling，你 23 周全碰过，却一个都没露出具体语境。

关键词从哪来？不用编。本周 Day 1 设计的客服 Agent 平台、Day 3 的异步向量化流水线、昨天 STAR 文档里的架构决策和踩坑记录，全是这些技术的真实动作和真实数据。简历的工作不是创造事实，是把埋在几百字故事里的事实挖出来，摆到十秒能扫到的位置。

## 核心知识

### 1. 一句话公式：动词 + 做了什么 + 技术栈 + 量化结果

先看出厂示范：

```
设计并实现基于 LangGraph 的多 Agent 客服系统，
Supervisor 路由 + HITL 审批，golden dataset 30 例回归通过率 92%
```

拆开看四段各干什么：

- 动词：「设计并实现」开头，说明这条是你主导的，不是围观。「负责」「参与」只描述岗位不描述成果，能换全换
- 做了什么：「Supervisor 路由 + HITL 审批」，具体到机制。面试官看到的不只是系统名，是你的架构决策
- 技术栈：LangGraph、Supervisor、HITL、golden dataset，全是 JD 高频词，而且每个都嵌在真实动作里。这是自然融入和堆砌的区别
- 量化结果：30 例、92%。两个数字让这条从「我做过」升级成「我做到了什么程度」

数字没测过怎么办？先补测。回归集跑一遍算通过率，检索算一遍命中率，半天就能做完。实在测不出的就量化规模：几个 Agent、几个工具、多少条用例、几轮迭代。规模数字也好过没有数字。

### 2. 改写示范：流水账版 → 成果版

三个里程碑逐个过。格式照抄，数字换成你 STAR 文档里的实测值，下面的数值只是举例。

**里程碑一：LangGraph 多 Agent 客服系统**

改前：

```
- 负责客服 Agent 系统的整体开发
- 使用 LangGraph 实现了多个 Agent
- 对系统进行了优化，解决了死循环等问题
```

改后：

```
- 设计并实现基于 LangGraph 的多 Agent 客服系统，Supervisor
  动态路由 3 个专职 Agent，覆盖咨询、查单、售后三类场景
- 引入 HITL 审批节点，退款等高危操作先经人工确认再执行
- 建设 30 例 golden dataset 回归集并接入评估流程，通过率 92%
```

逐行批注。第一行：「负责」换成「设计并实现」，主导权立刻可见；「多个 Agent」换成「3 个专职 Agent + 三类场景」，模糊数量变成具体规模，「多 Agent」这个词落进了语境。第二行：「解决了问题」被换成具体机制。你没解决「问题」，你解决的是「高危操作误执行」，手段是 HITL，这正是面试官爱追的架构决策。第三行：死循环修复这类工作看不见摸不着，回归集和通过率看得见，把工程工作翻译成可验证的成果靠的就是这一下。

**里程碑二：RAG 知识库问答**

改前：

```
- 开发知识库问答功能，使用 RAG 检索文档交给大模型回答
- 对检索效果进行了优化
```

改后：

```
- 搭建文档问答 RAG 全链路：解析、分块、向量化、混合检索、
  生成，支持 PDF 和 Markdown
- 针对纯向量检索的漏召回，引入 BM25 做混合检索，
  Top-5 命中率从 61% 提升到 83%
- 设计异步向量化流水线（消息队列 + 回调通知），大文档上传后
  立即可查询，页面不阻塞
```

批注。第一行把 RAG 从一个缩写展开成五个环节，说明你清楚数据怎么流，比写「熟悉 RAG」有说服力得多。第二行是黄金句式：针对什么问题、用什么手段、指标从多少到多少。第三行顺手把 Day 3 的队列设计装了进来，「消息队列」这个词也有了着落。

**里程碑三：MCP 工具集成**

改前：

```
- 为 Agent 添加工具调用能力，封装了一些 API
- 使用 MCP 协议接入工具
```

改后：

```
- 基于 MCP 协议封装 5 个业务工具（订单查询、物流跟踪等），
  由大模型通过 Function Calling 自主选择与传参
- 用 JSON Schema 做参数校验，模型幻觉参数在工具入口被拦截
- 设计工具超时与降级路径，外部接口超时自动转人工话术，
  不阻塞对话主链路
```

批注。第一行同时埋进 MCP 和 Function Calling 两个高频词，还写清了分工：MCP 是封装方式，Function Calling 是调用机制，这种精确本身就是加分。后两行把「封装了一些 API」写成有判断的设计：为什么校验（拦幻觉参数）、为什么降级（保主链路），每条都留着可追问的纵深，正好当 Day 6 模拟面试的弹药。

一个项目三到五条，每条一行到一行半，这是简历上一个项目的标准体量。

### 3. 技能栏：精通、熟练、了解的诚实梯度

技能栏不是罗列，是分档。三档定义先说死：

- 精通：能讲清原理、排查过疑难、能教别人。说实话，23 周的学习里几乎没东西够格写这两个字，除非某项你原本就有多年底子
- 熟练：独立做过完整功能，查文档能解决大部分问题。做完三个项目的主力技能放这档：TypeScript、LangGraph、RAG 链路
- 了解：上过手、跑得通、说得出原理和适用场景。MCP 的协议细节、没来得及深入的方向，放这档

为什么梯度本身是加分项：面试官从技能栏里挑靶子，「精通」是请他往深里问，「了解」是告诉他问浅一点。全写精通等于全暴露，诚实分档反而说明你知道自己几斤几两，这在工程岗是稀缺品质。第 1 周开始练的 TypeScript 敢写「熟练」，因为后面 20 多周的真实代码量垫着。

示例，按你实际碰过的技术调整：

```
- 语言与工程：熟练 TypeScript / Node.js，了解 Python
- Agent 开发：熟练 LangGraph（多 Agent 编排、HITL）、
  Function Calling，了解 MCP 协议机制
- RAG 与评估：熟练向量检索 / 混合检索，熟练 golden dataset 回归评估
- 后端与中间件：熟练 Redis 缓存防护、消息队列异步任务设计
```

每一项的自查标准一句话：这么写，被追问到什么深度我接得住？接不住就降一档。

### 4. 简历结构：一页原则

从上到下：

```
基本信息（姓名 / 电话 / 邮箱 / GitHub，一行）
技能（4-6 行，分域分档）
项目经历（3 个，每个：项目名 + 一句话定位 + 3-5 条 bullet）
教育背景（学校 / 专业 / 时间，一两行）
```

一页原则没有商量余地。HR 十秒扫一页已是极限，第二页约等于不存在。超页先砍什么：自我评价整段删，「学习能力强」「有热情」这类话没人信；与 AI 无关的早年经历压成一行；项目从 5 条砍到 3 条，而不是把每条砍成半句。条数可以少，每条的完整公式不能破。

两个细节。项目名直接写系统名，别写「毕业设计」「练习项目」，系统叫什么写什么，项目性质留给面试时坦诚说明。排序看相关性，与 JD 最贴的项目放最前，不必硬按时间倒序。

## 动手任务：重写三个项目，拼出简历初稿

手册任务：用量化结果 + 技术关键词重写项目描述。拆成 5 步，全程约 90 分钟，对着昨天 Day 4 的 STAR 文档做，不要凭记忆写。

**第 1 步：盘关键词（10 分钟）。** 找 3-5 份目标岗位 JD，把反复出现的词抄下来，LangGraph、RAG、MCP、Agent 评估、多 Agent、Function Calling 应该都在。和你的技术清单对交集，交集里的词今天必须埋进描述。

**第 2 步：挑数字（15 分钟）。** 打开 STAR 文档，把能量化的点全列出来：数据集多少例、通过率多少、命中率多少、几个 Agent、几个工具、耗时多少。没测过的标出来，今天补测，测完再写。

**第 3 步：逐条改写（40 分钟）。** 三个项目挨个过，每条 bullet 自查四问：开头是动作动词吗？有具体机制吗？关键词在语境里吗？有数字吗？四问全过才留，过不了的回 STAR 文档找料。

**第 4 步：写技能栏（10 分钟）。** 三档分格，每项过一遍「被追问到什么深度我接得住」，接不住的降档。

**第 5 步：拼装并做十秒测试（15 分钟）。** 按结构模板拼成完整简历，导出 PDF 确认正好一页。然后发给一个没看过你项目的朋友，给 TA 十秒，问 TA 记住了什么。TA 说出来的词就是 HR 眼中你的简历；什么都说不出来，回第 3 步重改。

::: tip 关键词自查
把初稿粘进文本编辑器，用查找功能逐个搜第 1 步盘出的关键词。搜不到的，要么你确实没用过（别硬塞），要么描述把它藏得太深（回去改写）。判断埋得自然不自然：技术词出现在动作里叫融入，单独排成一行名词叫堆砌。
:::

## 常见踩坑

**坑 1：「熟悉 XX 原理」没细节，必被追问打穿。** 简历上每个技术名词都是你亲手给面试官划的考点。写了 Supervisor 路由，就要答得出为什么不用固定顺序；写了 HITL，就要说得出不审批会出什么事。面试问题不是凭空来的，是从你写的词里长出来的。

**坑 2：关键词堆砌。** 「熟悉 LangGraph/RAG/MCP/多 Agent/Function Calling」排成一行，扫描能过，人眼一看就烦。关键词必须活在动作里：「引入 BM25 做混合检索，命中率 61% 到 83%」里的检索是真的，孤零零躺着的「RAG」是假繁荣。堆砌暴露的恰恰是没真做过。

**坑 3：舍不得删无关经历。** 简历不是人生履历总账，是针对一个岗位的定向材料。与 AI 无关的早年工作压成一行，无关证书、学生会经历直接删，腾出的每一行都给项目。你心疼的那段经历，HR 十秒里根本看不见。

**坑 4：把「会表述」理解成「能吹」。** 边界说死：事实不能虚构，没用的技术不写、没测的数字不编、学习项目不装成商业项目，AI 岗面试往深追三层就露馅。表述是选角度：动词选主导性的（前提是你真主导），数字选最有说服力的（前提是真实可复现），功能点选与 JD 最相关的。检验就一条：被追问三层，还答得上来吗？

**坑 5：动词全是「负责」「参与」。** 这两个词放哪份简历上都成立，所以等于没说。开头换成有信息量的动词：设计、实现、搭建、引入、封装、排查、重构。一个动词就暴露你在这条描述里扮演的角色，别浪费。

## 自测问题

先自己答，再展开对照。答不上来的，回对应小节看一遍。

1. 简历筛选的两道关卡分别筛掉什么样的简历？

::: details 参考答案
第一关人眼十秒扫结构，筛掉没有成果导向、全是职责描述的；第二关关键词初筛，筛掉 JD 高频词零出现的。对策分别是公式化 bullet，和把交集关键词自然埋进动作描述。
:::

2. 「负责 Agent 系统开发，使用 LangGraph 框架」按公式缺了什么？

::: details 参考答案
公式是动作动词 + 做了什么 + 技术栈 + 量化结果。这条动词零信息，机制细节没有，量化结果没有；LangGraph 算技术栈在位，但只是挂名，没嵌进动作。
:::

3. 三档怎么划线？为什么 23 周的学习几乎不该出现「精通」？

::: details 参考答案
精通是能讲原理、排疑难、教别人；熟练是独立做过完整功能；了解是上过手、说得出适用场景。精通需要时间和踩坑量打底，23 周够把主力技能练到熟练。写高一档，追问就深一档，接不住整份简历的可信度一起塌。
:::

4. 项目没有现成数字，量化结果从哪来？

::: details 参考答案
先补测：回归集跑通过率，检索算命中率，接口掐耗时。测不出的量化规模：几个 Agent、几个工具、多少条用例、几轮迭代。规模数字也好过没有数字，什么都数不出来，这件事可能就不值得写。
:::

5. 「不造假但会表述」的检验标准是什么？

::: details 参考答案
事实层不虚构：没用的技术不写、没测的数字不编、项目性质不装。表述层选角度：主导性动词、最有说服力的真实数字、与 JD 相关的功能点。综合检验：被追问三层还答得上来，就站得住。
:::
